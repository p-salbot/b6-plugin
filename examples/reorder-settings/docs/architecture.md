# Architecture

Rows are added in the same change as the code they describe.

| Section | What holds today | What it means for changes | Why |
|---|---|---|---|
| Storage file | `reorder/storage.py` keeps the settings in one SQLite file. The default is `reorder.db` in the project root, found from the location of the code, not the current folder (`DEFAULT_DB_PATH`). `ReorderStore` takes any other path, or `:memory:`. | Tests must pass their own path or `:memory:`, never the default. Only Python standard library modules may be used. | [0001](decisions/0001-sqlite-file-with-python-tool.md) |
| Table | Table `reorder` (item number, min qty, reorder qty, supplier). The item number is the primary key and is matched ignoring upper/lower case for the ASCII letters A-Z only (SQLite `NOCASE`); for example `Ü` and `ü` count as different. `CHECK` rules repeat the input rules. The table is created if missing. | A new rule must be added both in the Python checks and in the table `CHECK`. Changing the table needs a plan for existing data files. Full Unicode case folding would need a change to the table. | [0001](decisions/0001-sqlite-file-with-python-tool.md) |
| Saving | `save` is one SQL statement inside one transaction (insert, or update if the item exists). If anything fails, nothing is changed. An update keeps the stored spelling of the item number. | Never delete and insert as separate steps. All SQL uses `?` parameters; never put text into the SQL string. | [0001](decisions/0001-sqlite-file-with-python-tool.md) |
| Input checks | Before writing, text is trimmed and must not be empty. Min qty is a whole number 0 or more, reorder qty a whole number 1 or more (`bool` and `float` are refused). A bad value raises `ValidationError` naming the field and the rule. | Callers get `ValidationError` with a message naming the field and the rule; keep messages that way. | [0001](decisions/0001-sqlite-file-with-python-tool.md) |
| Reading | `read` returns one `Item` or `None`; `list_all` returns all items sorted by item number ignoring case. | Callers only get `Item` values or `None`. | [0001](decisions/0001-sqlite-file-with-python-tool.md) |
| Command line | `python -m reorder` (`reorder/cli.py`, started by `reorder/__main__.py`) has the commands `show ITEM`, `save ITEM --min N --reorder N --supplier TEXT` and `list`. `main(argv, store)` returns the exit code: 0 ok, 1 for an unknown item or a refused input, 2 for a usage mistake (left to `argparse`). Messages for errors go to standard error, results to standard output. Without a `store` it opens the default file and closes it at the end. `__main__.py` calls `configure_output` so that standard output and error are always UTF-8 and replace a character instead of failing. | Tests call `main` with a `ReorderStore(":memory:")`. The CLI holds no input rules of its own: `--min` and `--reorder` are turned into numbers only if, after removing spaces at the ends, they are an optional sign and the digits 0-9 (so `1_0` and full-width digits are not numbers); otherwise the text is passed on and the storage check gives the message. A new rule goes into `storage.py`, not into the CLI. | [0001](decisions/0001-sqlite-file-with-python-tool.md) |
