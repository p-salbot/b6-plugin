## Findings

1. **`--min`/`--reorder` conversion is too lenient (R-004)**, `reorder/cli.py:9-15`. `int()` accepts `1_0` (read as 10), full-width or other Unicode digits, and spaces around the value. `1_0` and non-ASCII digits are not whole numbers to a non-expert user, and they are saved silently with exit 0. Verdict on the worker's open point: `" 5 "` is acceptable (consistent with trimming text, R-004), but `1_0` is a defect. Fix: convert only text that is, after `strip()`, an optional sign followed by ASCII digits `0-9` (for example `re.fullmatch(r"[+-]?[0-9]+", text.strip())`); otherwise pass the text on so storage gives its message. Add a test (for example `--reorder 1_0` refused, data unchanged), and keep the architecture row in line.
2. **Output with special characters breaks when output is redirected or piped on Windows** (`reorder/cli.py` prints; `reorder/__main__.py`). When stdout is not a console, Python 3.13 here uses cp1252. Trial: `Müller` reached the pipe as cp1252 bytes and the reader showed `M�ller`. This is the main chat's `M?ller`: the data is correct and the reading program decoded cp1252 bytes as something else. Worse, `save L-1 ... --supplier "Łódź"` stored the row and then crashed with `UnicodeEncodeError`, a traceback and exit 1. The user is told it failed although it was saved, which goes against "clear messages", "success: exit code 0" and the intent of R-005 ("other special characters work"). `show L-1 > out.txt` printed half the fields and then a traceback. Effect on the owner's real use: typed directly in an interactive Windows console (cmd, PowerShell, Windows Terminal), Python writes Unicode to the console and both names print correctly. I could not check this myself because my shell is a pipe, so a manual trial by the owner is needed. Only redirected or piped use (`list > items.txt`, piping into another command) is hit. Fix (choice for the main chat or owner, not decided by me): for example, in `__main__.py` call `sys.stdout.reconfigure(errors="replace")` and the same for stderr, so output never crashes, or write UTF-8 when not a console. Add a test that a save whose output cannot be encoded still returns 0, or document the limit in the README (step 3).
3. **Label difference "Reorder quantity" (error message) vs "Reorder qty" (show/save/list output)**: acceptable, not a defect. The brief prescribes `Reorder qty` for output and says to show the `ValidationError` text unchanged, and `storage.py` may not be changed in this step. Both name the field clearly. Aligning them would be a later storage change, for the owner to decide.
