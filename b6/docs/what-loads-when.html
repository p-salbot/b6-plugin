What loads when
Sprievodca · plugin b6

Čo sa načíta kedy

Claude si v jednom chate pamätá len to, čo sa doň načítalo. Keď sa kontext zaplní, práca sa spomalí, zdražie a robí sa v nej viac chýb. Plugin b6 preto načítava veľa vecí až vtedy, keď sa naozaj použijú.

Šesť pojmov

Vždy

Kontext

Všetko, čo Claude v jednom chate drží v hlave: tvoje správy, jeho odpovede, prečítané súbory, výstupy príkazov. Rastie s každou správou; zmenší sa až pri zhustení (compact) alebo v novom chate. Plný kontext znamená pomalšiu a drahšiu prácu a viac chýb. Preto je lepšie čítať málo a až vtedy, keď to treba.

Pri použití

Skill

Textový súbor s postupom. Jeho krátky popis (v hlavičke) Claude vidí vždy. Celé telo SKILL.md sa načíta, až keď popis sedí na tvoju požiadavku. Obyčajná otázka, ktorá nemení súbory, ho nepotrebuje; otázky o stave práce alebo o postupe („čo je rozrobené“, „kde sme“, „ako to funguje“) workflow načítajú.

Pri kroku

Referencia

Súbor, ktorý skill otvorí iba v kroku, ktorý ho potrebuje: templates.md (tvary dokumentov) a models.md (úrovne modelov a odhad tokenov) v skille workflow. Pri jasnej drobnej zmene sa neotvorí vôbec.

Vlastný kontext

Agent

worker a reviewer. Každý začína s čistým kontextom: nevidí chat; okrem vlastných pokynov (agents/<meno>.md) a CLAUDE.md projektu dostane len zadanie (brief). Vráti najviac 20 riadkov, takže hlavný chat sa nezaplní. Reviewer je vždy nový, nevidel prácu workera.

Pri štarte

Hook SessionStart

Jeden riadok, ktorý sa vloží na začiatku chatu: plugin je aktívny a pred každou zmenou súboru sa má načítať skill b6:workflow. Nič iné sa tým nenačíta.

Podľa potreby

Súbory projektu

CLAUDE.md sa načíta vždy. Priečinky ctx/ (požiadavky, úlohy, plány) a docs/ (architektúra, rozhodnutia) sa čítajú iba vtedy, keď ich krok potrebuje.

Čo je v kontexte v ktorom momente

Príklad: jedna zmena veľkosti M, od štartu chatu po uzavretie. Hlavný chat je kontext, ktorý rastie. Agenti pracujú vo vlastnom kontexte a do hlavného vrátia len krátku správu.

MomentPribudne do hlavného chatuNenačíta sa
Štart chatu vždy CLAUDE.md, krátke popisy skillov a agentov, riadok z hooku SessionStart telá skillov, referencie, ctx/, docs/
Zadanie zmeny skill telo workflow, ktorý na začiatku prečíta ctx/TASKS.md, ak existuje; potom podľa veľkosti M skill brainstorming plan, build, wrap-up, agenti
Brainstorming referencia templates.md pri zápise požiadaviek; súbory ctx/, docs/ a existujúci kód, ktoré sú k téme; na konci sa opýta na jazyk dokumentov a po schválení zapíše ctx/, docs/ a riadky do CLAUDE.md podľa templates.md models.md
Plán skill telo plan; súbory ctx/requirements.md a návrh ctx/plans/<dátum>-<slug>-design.md; referencie templates.md a models.md (úrovne a odhad tokenov) telo build, agenti
Krok stavby skill telo build; referencia templates.md (zadanie, recenzia, SUMMARY.md); plán a SUMMARY.md; kontrolu spúšťa hlavný chat sám; od worker len správa (najviac 20 riadkov) ostatné kroky; práca workera v hlavnom chate
Recenzia v hlavnom chate od reviewer len verdikt, očíslované nálezy a cesta k súboru review-<n>.md čo reviewer čítal
Uzavretie skill telo wrap-up; referencia templates.md; súbory, ktoré treba aktualizovať (ctx/requirements.md, ctx/TASKS.md, docs/architecture.md); review-<n>.md a SUMMARY.md behu; met sa zapíše až po OK od nového recenzenta models.md; agenti len keď treba opraviť architektúru alebo odkazy

Pri malej zmene S (jeden či dva existujúce súbory) sa brainstorming, plán ani šablóny nečítajú, v ctx/ sa nevytvárajú žiadne súbory a ctx/TASKS.md sa nemení. Stačí workflow (ten pri štarte prečíta ctx/TASKS.md, ak existuje), zmena cez worker a kontrola cez reviewer. Dôkaz sa zapíše do ctx/requirements.md iba vtedy, keď sa zmena dotýka požiadavky, ktorá tam už je.

Čo z toho vyplýva

  • Dlhý chat spomaľuje a draží. Novú úlohu začni v novom chate; pokračovanie je v SUMMARY.md a v ctx/.
  • Popis skillu rozhoduje, či sa skill otvorí. Preto obsahuje slová, ktoré ľudia naozaj používajú.
  • Jeden krok robí agent s čistým kontextom: nevidí chat, preto zadanie musí byť úplné.
  • Do CLAUDE.md patrí len to, čo platí vždy. Čo platí iba pri jednej práci, patrí do skillu alebo do dokumentu v ctx/ či docs/.

Guide · b6 plugin

What loads when

In one chat, Claude keeps in mind only what was loaded into it. When the context fills up, work gets slower, costs more and makes more mistakes. So the b6 plugin loads many things only at the moment they are really used.

Six terms

Always

Context

Everything Claude holds in mind in one chat: your messages, its answers, files it read, command outputs. It grows with every message; it shrinks only when it is compacted or in a new chat. A full context means slower, more expensive work and more mistakes. That is why it is better to read little, and only when needed.

When used

Skill

A text file with a procedure. Its short description (in the header) is always visible to Claude. The whole SKILL.md body loads only when the description fits your request. A plain question that changes no file does not need it; questions about the work or the method ("what is in progress", "where are we", "how does this work") do load workflow.

In one step

Reference

A file a skill opens only in the step that needs it: templates.md (shapes of documents) and models.md (model levels and token estimate) in the skill workflow. For a clear small change it is never opened.

Own context

Agent

worker and reviewer. Each starts with a fresh context: it does not see the chat; besides its own instructions (agents/<name>.md) and the project CLAUDE.md it gets only the brief. It returns at most 20 lines, so the main chat does not fill up. The reviewer is always new and did not see the worker's work.

At start

SessionStart hook

One line added at the start of the chat: the plugin is active and the skill b6:workflow must be loaded before any file is changed. Nothing else is loaded by it.

As needed

Project files

CLAUDE.md is always loaded. The folders ctx/ (requirements, tasks, plans) and docs/ (architecture, decisions) are read only when a step needs them.

What is in context at which moment

Example: one change of size M, from the start of the chat to wrap-up. The main chat is the context that grows. Agents work in their own context and return only a short report to the main chat.

MomentAdded to the main chatNot loaded
Start of chat always CLAUDE.md, short descriptions of skills and agents, the SessionStart hook line skill bodies, references, ctx/, docs/
Request for a change skill body of workflow, which at the start reads ctx/TASKS.md if it exists; then, for size M, skill brainstorming plan, build, wrap-up, agents
Brainstorming reference templates.md when requirements are written; files ctx/, docs/ and existing code related to the topic; at the end it asks for the document language and, after approval, writes ctx/, docs/ and the CLAUDE.md lines from templates.md models.md
Plan skill body of plan; files ctx/requirements.md and the design ctx/plans/<date>-<slug>-design.md; references templates.md and models.md (levels and token estimate) body of build, agents
Build step skill body of build; reference templates.md (brief, review, SUMMARY.md); the plan and SUMMARY.md; the main chat runs the check itself; from worker only the report (at most 20 lines) other steps; the worker's own work
Review in the main chat from reviewer only the verdict, numbered findings and the path to the file review-<n>.md what the reviewer read
Wrap-up skill body of wrap-up; reference templates.md; files to update (ctx/requirements.md, ctx/TASKS.md, docs/architecture.md); the run's review-<n>.md and SUMMARY.md; met is set only after OK from a fresh reviewer models.md; agents only if architecture or links need a fix

For a small change of size S (one or two existing files), brainstorming, the plan and the templates are not read, no files in ctx/ are created and ctx/TASKS.md is not changed. workflow (which reads ctx/TASKS.md at the start if it exists), the change by worker and the check by reviewer are enough. Evidence goes into ctx/requirements.md only if the change touches a requirement that is already there.

What follows from this

  • A long chat makes work slower and more expensive. Start a new task in a new chat; the continuation is in SUMMARY.md and in ctx/.
  • The description of a skill decides whether the skill opens. That is why it holds words people really use.
  • One step is done by an agent with a fresh context: it does not see the chat, so the brief must be complete.
  • Only what is always true belongs in CLAUDE.md. What holds for one piece of work belongs in a skill or in a document in ctx/ or docs/.
